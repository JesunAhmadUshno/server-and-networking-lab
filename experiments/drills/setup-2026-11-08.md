# P23 drill VM setup notes, 2026-11-08

Test VM for the P23 recovery drills (H2, H3), built on the R610 host (192.168.1.50).
Day 0 host setup (repo clone, /opt/p23, cron jobs, trial order) is recorded in PR #14.
This file records Step 1: the VM build, its storage pool, the uid/gid alignment, and how files move.

## Base image

- Image: noble-server-cloudimg-amd64.img (Ubuntu 24.04 cloud image), downloaded on the host from cloud-images.ubuntu.com to /tmp/noble.img, 621,284,352 bytes.
- Converted with qemu-img to /var/lib/libvirt/images/p23/base.qcow2 (backing base, kept read-only in practice).
- Disks created in /var/lib/libvirt/images/p23/: os.qcow2 20G (backing file base.qcow2), d1.qcow2 4G, d2.qcow2 4G, d3.qcow2 4G.

## VM creation (command actually run on the host, under sudo)

```
virt-install --name p23-drill --network network=labnet --memory 2048 --vcpus 2 --disk /var/lib/libvirt/images/p23/os.qcow2 --disk /var/lib/libvirt/images/p23/d1.qcow2 --disk /var/lib/libvirt/images/p23/d2.qcow2 --disk /var/lib/libvirt/images/p23/d3.qcow2 --cloud-init user-data=/tmp/p23seed/user-data,meta-data=/tmp/p23seed/meta-data --os-variant ubuntu24.04 --import --noautoconsole
```

- Result: domain p23-drill running, 2048 MB RAM, 2 vcpus.
- Cloud-init seed (/tmp/p23seed/ on the host): user drill (shell /bin/bash, sudo NOPASSWD), ssh_pwauth true, packages lvm2 and git. A throwaway random password for drill was generated on the host and injected via chpasswd in the seed. The value is recorded nowhere; the host copy lives only in /tmp/.vmpw (mode 600) and host-side access uses sshpass -f /tmp/.vmpw.
- Network: labnet only (10.99.0.0/24, isolated, no route out). DHCP lease at build time: 10.99.0.181, MAC 52:54:00:9b:c1:ba, hostname p23-drill. Re-read the lease before each session with: virsh net-dhcp-leases labnet (works as brimwood, no sudo needed).
- Host tooling: sshpass was not present on the host; installed with apt-get install -y sshpass (sudo).

## Inside the VM (setup script run as drill)

```
vgcreate drillvg /dev/vdb /dev/vdc /dev/vdd
lvcreate -l 100%FREE -n data drillvg
mkfs.ext4 on the data LV, mounted at /srv/data (12G total)
cp -a /usr/share/doc /srv/data/   (sample data)
mkdir /srv/backup /srv/restore    (on the VM root filesystem)
```

- The three 4G disks appear in the VM as /dev/vdb, /dev/vdc, /dev/vdd. The drillvg pool mirrors the labvg idea at small scale: H3 removes one member disk and rebuilds.
- An in-VM git clone of this repo failed (no route out of labnet), as expected. The repo is ferried in by the host, see below.

## How files move between host and VM

- labnet has no route to the internet or the LAN. The host ferries every file.
- Host to VM and back: scp -p over labnet (the -p flag preserves mtimes; drill.sh uses archive mtime for backup age). Host side runs sshpass -f /tmp/.vmpw scp/ssh as drill@10.99.0.181.
- Repo ferry (run on the host): scp -rp ~/server-and-networking-lab drill@10.99.0.181:/home/drill/
  Verified: 381,798 bytes on both ends; src/drill.sh sha256 e6636fb2a88560c1803d6c7d8f81dc9908a6e5e88d02942a89b42e29c2e0b29c matches the host clone.
- H3 note: the VM's own backup goes to a directory on the host over labnet (the host is the VM's off-server copy target).

## UID/GID alignment (done 2026-11-08, before trial 1)

Reason: the H2 restore compares a host /etc archive inside the VM with tar --compare. Where a user or group name exists on both machines with different numbers, tar maps by name and the compare reports Uid differs / Gid differs. Intersecting names were aligned to the host numbers.

- First pass (partial): a swap attempt moved VM landscape to 108:109 and parked tss at a temporary 2000:104. Ownership of /var/lib/landscape, /var/log/landscape and /var/lib/tpm was repaired by name afterwards.
- Final pass (one coordinated renumber, run inside the VM as root): files owned by each affected old uid/gid were recorded first, /etc/passwd and /etc/group were edited directly to the host numbers, then ownership was reapplied from the recorded path lists.
- Users set to host values: messagebus 101:102, syslog 103:104, uuidd 104:105, pollinate 102:1, tcpdump 105:107, landscape 107:109, tss 106:108, polkitd 991:991, fwupd-refresh 989:989, systemd-resolve 992:992, systemd-timesync 997:997.
- Groups set to host values: lxd 101, messagebus 102, _ssh 103, syslog 104, uuidd 105, rdma 106, tcpdump 107, tss 108, netdev 110, fwupd-refresh 989, crontab 990, polkitd 991, systemd-resolve 992, render 993, kvm 994, sgx 995, input 996, systemd-timesync 997. The VM-only group admin moved 110 to 2010 to free 110 for netdev.
- Verification (independent diff, host vs VM, every name present on both machines): 91 names checked, 0 differences.
- Names that exist only on the host (for example brimwood 1000, xrdp 128, dnsmasq 999) were not created in the VM: tar falls back to the numeric id when a name is absent. If the instrument check still reports a differs line for one of them, that user or group gets created in the VM and the check is repeated before trial 1.
