# server-and-networking-lab

**Question.** Can a solo-run server detect its own drift and recover from
a disk or configuration loss within targets set in advance?

**Headline.** On its first live run the checker caught real drift: two
firewall ports opened after the baseline. I checked what was listening
before changing anything, kept both services, recorded why
(docs/decisions/0001), fixed the capture bug the run exposed, and kept
the flawed capture as captured. The current live capture passes 10 of 10.
Recovery (three timed tests) is planned and not yet measured.

**Field.** Systems and infrastructure. **Job family.** Infrastructure and
platform engineering.

**Verdict.** Functional, not pre-registered. Tests pass in CI on Python
3.11 and 3.12 and the results are reproduced from the evidence by one
command. Recovery tests are planned in PROPOSAL.md, a draft until its
pass lines are locked by tag.

Live dashboard: https://jesunahmadushno.github.io/server-and-networking-lab/

## Reproduce

```text
python3 src/run_check.py experiments/snapshots/r610-snapshot-2026-11-08-live.json
python3 -m unittest discover -s tests -p "test_*.py" -v
python3 src/make_results.py --check
```

Python 3 only, no dependencies. A fresh capture is taken on the server
with src/capture_snapshot.sh (read-only) and saved as a new dated file
in experiments/snapshots/.

Evidence honesty: the 2026-10-26 snapshot is transcribed from the build record; the 2026-11-07 and 2026-11-08 snapshots were captured on the server by src/capture_snapshot.sh.

## Layout

| Path | What it holds |
| --- | --- |
| PROPOSAL.md | Question, prior work, hypotheses and targets, design (draft, locked by tag) |
| REPORT.md | Baseline, the drift finding, results, limits |
| src/ | The checker, the capture script, the results script |
| tests/ | Unit and mutation tests (one failing case per check) |
| experiments/snapshots/ | Dated server snapshots, never edited after capture |
| results/baseline.json | Every snapshot scored, regenerated by src/make_results.py |
| docs/decisions/ | Records of hard-to-reverse choices |
| site/ | The live dashboard, built from the files above |
